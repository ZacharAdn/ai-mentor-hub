מצב א: ליצור ריפו חדש בארגון

כ-4 דקות
  1. בדף הארגון לחצו New repository (הכפתור הירוק).
  2. בשדה Owner ודאו שנבחר Technion-016834 ולא השם שלכם.
  3. תנו שם לפרויקט באותיות לטיניות וללא רווחים, בחרו Private, וסמנו Add a README file.
  4. לחצו Create repository.
  5. מורידים את הריפו אליכם: ב-VS Code בחרו Clone Repository, הדביקו את הקישור של הריפו, ופתחו את התיקייה לפני שמתחילים לעבוד.
⚠️ הריפו נוצר בחשבון הפרטי במקום בארגון?
ברירת המחדל של גיטהאב היא החשבון הפרטי שלכם, וזו טעות נפוצה. לא מוחקים את הריפו, כי מחיקה לא ניתנת לשחזור. במקום זה:
  1. פתחו ריפו חדש בארגון, בדיוק כמו בשלב הזה, עם README.
  2. ב-README של ריפו הארגון הדביקו קישור לריפו הפרטי שלכם.
  3. בריפו הפרטי: Settings, אחר כך Collaborators, Add people, והוסיפו את המשתמש ZacharAdn. לחלופין הפכו אותו ל-Public (Settings, גללו לתחתית, Change visibility).
כשתרצו להעביר את הקוד עצמו לארגון, השתמשו בשלב 4.
4

מצב ב: לדחוף קוד קיים לריפו בארגון

כ-5 דקות
  1. צרו ריפו ריק בארגון כמו בשלב 3, אבל בלי לסמן README.
  2. פתחו את התיקייה של הפרויקט ב-VS Code, הפעילו קלוד קוד, והדביקו לו את הפרומפט הבא (החליפו את REPO-NAME בשם הריפו):
    I have a local project folder with existing code. Push it to this GitHub repo inside the course organization: https://github.com/Technion-016834/REPO-NAME Set it as the remote (replace any existing remote), make sure venv folders and secrets are not committed, commit, and push to main. Tell me if anything is missing.
ℹ️ אותו דבר בטרמינל
בתוך תיקיית הפרויקט:
git remote -v git remote set-url origin https://github.com/Technion-016834/REPO-NAME.git # אין עדיין remote? במקום השורה הקודמת: # git remote add origin https://github.com/Technion-016834/REPO-NAME.git git branch -M main git push -u origin main
אם הקוד היה מחובר לריפו בחשבון האישי, set-url מחליף את היעד. הקוד נשאר גם בחשבון האישי, אבל מעכשיו דוחפים רק לארגון.
💡 הדחיפה נכשלת על קבצים כבדים?
כנראה תיקיית venv נכנסה לקומיט. בקשו מקלוד קוד להוסיף אותה ל-.gitignore ולהסיר אותה מהקומיט.
