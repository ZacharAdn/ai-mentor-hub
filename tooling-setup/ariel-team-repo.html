המתכנת מכין ריפו אחד לצוות, בתוך הארגון

כ-5 דקות · פעם אחת לצוות · השאר מחכים לשלב 3
ריפו אחד לכל צוות, בתוך הארגון ולא בחשבון הפרטי. אם כבר יש לכם ריפו בחשבון הפרטי של מישהו, מעבירים אותו לארגון ולא פותחים חדש: כך ההיסטוריה והקבצים נשמרים.
🆕 עוד אין לנו ריפו
  1. היכנסו ל-github.com/organizations/Ariel-Vibe-Algorithm/repositories/new
  2. בשדה Owner בדקו שכתוב Ariel-Vibe-Algorithm, ולא שם המשתמש שלכם.
  3. תנו לפרויקט שם קצר באנגלית, למשל caffeine-sleep.
  4. סמנו Add README ולחצו Create repository.
📦 כבר יש לנו ריפו בחשבון פרטי

רק מי שהריפו בחשבון שלו עושה את זה, ורק אחרי שאישר את ההזמנה לארגון בשלב 1.

  1. בדף הריפו: Settings, וגוללים עד הסוף, לאזור האדום Danger Zone.
  2. לוחצים Transfer ownership, ובוחרים או מקלידים את הארגון: Ariel-Vibe-Algorithm.
  3. מקלידים את שם הריפו לאישור, ולוחצים על הכפתור לאישור ההעברה.
  4. הריפו עובר לכתובת חדשה, github.com/Ariel-Vibe-Algorithm/<repo-name>. הקישור הישן מפנה אליה לבד, אבל ב-README כדאי לעדכן.
⚠️ כבר שיבטתם את הריפו הישן למחשב?
ממשיכים לעבוד באותה תיקייה, ‏GitHub מפנה את הדחיפות לכתובת החדשה. אם משהו נכשל, משבטים מחדש לפי שלב 3.

בשני המקרים: מוסיפים את חברי הצוות

  1. בדף הריפו: Settings, ואז Collaborators and teams.
  2. לחצו Add people, והקלידו את שם המשתמש של כל חבר צוות. בחרו הרשאת Write.
  3. שלחו לחברי הצוות את כתובת הריפו בקבוצה של הצוות.
⚠️ לא מוצאים חבר צוות לפי השם?
חפשו לפי שם המשתמש שלו או לפי המייל של החשבון שלו. אם עדיין לא נמצא, כתבו בקבוצה.

כל אחד מוריד את הריפו למחשב (Clone)

כ-5 דקות · כל חבר צוות, כולל המתכנת
שיבוט, Clone, מוריד עותק של הריפו למחשב ומשאיר אותו מחובר ל-GitHub. כך מה שאתם שומרים מגיע לצוות, ומה שהצוות שומר מגיע אליכם.
⚠️ לא מוצאים את Clone? זה תקין, וכך עוקפים
כשתיקייה כבר פתוחה ב-VS Code, חלונית Source Control לא מציעה Clone בכלל, לא בכפתור ולא בשלוש הנקודות. היא מציעה רק Initialize Repository, ואותו לא לוחצים. ‏Clone מופיע שם רק כשאין שום תיקייה פתוחה.
הדרך שעובדת תמיד, עם תיקייה פתוחה או בלי: חלון הפקודות, Git: Clone. זו הדרך בהמשך השלב.

לפני הכול: איפה הריפו יישב

  1. צרו במחשב תיקייה לפרויקטים, מחוץ לענן. ב-Windows למשל C:\projects, ובמק תיקייה בשם projects בתיקיית הבית.
    ⚠️ למה לא במסמכים או על שולחן העבודה?
    ב-Windows התיקיות האלה מסתנכרנות לרוב ל-OneDrive, ובמק לפעמים ל-iCloud. הסנכרון שובר את הריפו. זו הייתה התקלה של כמה סטודנטים בטכניון.
  2. בדף הריפו ב-GitHub לחצו על הכפתור הירוק Code, ובלשונית HTTPS העתיקו את הכתובת.
✅ הדרך הרגילה: Git: Clone
  1. ב-VS Code לחצו Ctrl+Shift+P, ובמק Cmd+Shift+P. נפתח חלון פקודות בראש המסך.
  2. הקלידו Git: Clone, בחרו אותו ולחצו Enter.
  3. הדביקו את הכתובת מ-GitHub ולחצו Enter.
  4. נפתח חלון לבחירת תיקייה. בחרו את תיקיית הפרויקטים ולחצו Select as Repository Destination. אם VS Code מבקש להתחבר ל-GitHub, אשרו בדפדפן.
  5. ‏VS Code יוצר בתוך תיקיית הפרויקטים תיקייה חדשה בשם הריפו, ומוריד אליה את הקבצים. כך זה אמור להיות.
  6. בסוף נשאלת שאלה אם לפתוח את הריפו. לחצו Open: החלון עובר לתיקייה של הריפו, ומעכשיו עובדים רק בה.
⚠️ לא לבחור Add to Workspace
אם תיקייה אחרת הייתה פתוחה, השאלה מציעה גם Add to Workspace. זה פותח שתי תיקיות זו לצד זו, וקל לעבוד, ולתת לקלוד לעבוד, בתיקייה הלא נכונה. בוחרים Open, או Open in New Window אם רוצים לשמור גם את החלון הקודם.
📂 כבר פתחתי תיקייה ריקה לפרויקט, ואני רוצה את הריפו בדיוק בה

ככה לא נוצרת תיקייה נוספת, והחלון נשאר על התיקייה שפתוחה. עובד רק אם התיקייה ריקה לגמרי.

  1. פתחו את הטרמינל של VS Code: בתפריט Terminal בוחרים New Terminal. הטרמינל נפתח בתיקייה שפתוחה.
  2. הקלידו git clone, רווח, הדביקו את הכתובת, רווח, ונקודה בסוף. למשל:
    git clone https://github.com/Ariel-Vibe-Algorithm/caffeine-sleep.git .
    הנקודה בסוף אומרת לגיט: לתוך התיקייה הזאת, בלי ליצור תיקייה חדשה.
  3. הקבצים של הריפו מופיעים בסרגל הקבצים, וחלונית Source Control מזהה את הריפו. אם היא לא מתעדכנת, סגרו ופתחו את VS Code.
⚠️ הודעת already exists and is not an empty directory?
התיקייה לא ריקה, וגיט לא משבט לתוך תיקייה שיש בה קבצים. חוזרים לדרך הרגילה, Git: Clone.
⚠️ לא לוחצים Initialize ולא Publish
‏Initialize Repository ו-Publish to GitHub יוצרים ריפו נפרד, בחשבון הפרטי, שלא מחובר לריפו של הצוות. אם הם מוצעים לכם, אתם בתיקייה הלא נכונה: משבטים לפי השלב הזה, ופותחים את התיקייה ששובטה. זו התקלה הכי נפוצה בטכניון.
💡 הודעת Repository not found?
המתכנת עוד לא הוסיף אתכם ב-Collaborators, או שלא אישרתם את ההזמנה לארגון, או ש-VS Code מחובר לחשבון GitHub אחר. בדקו את שלושתם, בסדר הזה.

השינוי הראשון: קובץ עם השם שלכם

כ-5 דקות · כל חבר צוות
כל אחד יוצר קובץ משלו, כדי ששני אנשים לא יערכו את אותה שורה באותו זמן. שמירה עם הסבר נקראת קומיט (Commit), והשליחה שלה ל-GitHub נקראת דחיפה (Push).
  1. ב-VS Code צרו קובץ חדש בשם שלכם באנגלית, למשל dana.md, וכתבו בו שורה אחת: התפקיד שלכם בצוות. שמרו.
  2. פתחו את Source Control, האייקון של הענף בסרגל הצד. הקובץ מופיע תחת Changes.
  3. כתבו הודעה קצרה בשדה שמעל הכפתור, למשל add dana, ולחצו Commit.
  4. לחצו Sync Changes. אם נפתח חלון התחברות בדפדפן, אשרו אותו.
  5. רעננו את דף הריפו ב-GitHub. הקובץ שלכם שם.
💡 הדחיפה נדחתה?
חבר צוות דחף לפניכם. זה תקין, ושום דבר לא אבד: לוחצים שוב Sync Changes, ו-VS Code מושך קודם את השינוי שלו ואז דוחף את שלכם. אם זה נדחה שוב, כתבו בקבוצה.
⚠️ הודעה על divergent branches?
חסרה הגדרה, בדרך כלל במק. בטרמינל של VS Code:
git config --global pull.rebase false
ואז שוב Sync Changes.
⚠️ שגיאת GH007, על מייל פרטי?
ב-github.com/settings/emails מורידים את הסימון מ-Block command line pushes that expose my email, ולוחצים שוב Sync Changes.
💡 ‏Sync Changes נתקע בלי הודעה?
כנראה מחכה לכם חלון התחברות בדפדפן. חפשו אותו, ואשרו.
ℹ️ אותו דבר בטרמינל
git add . git commit -m "add dana" git pull git push
