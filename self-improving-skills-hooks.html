A System That Improves Itself

Skills & Hooks in Claude Code — and why it's the exact same Judge/eval loop you built, just one layer up.

The one-sentence idea

Start from something you already built.

You built a Judge: a rubric scores each AI summary 1–5, the best one wins, and a low score triggers a fallback. Claude Code's skill system does the exact same thing — but the thing being scored is not a football summary, it's a skill run. Score it 1–5, and the system routes itself to fix, self-improve, or bank the win. Same eval loop. One layer up.

📌 Hold this anchor the whole way: rubric → score → improve is your idea. Everything below is that idea applied to the tools instead of the summaries.

Skill vs Hook — who decides?

The whole distinction is one question: does the model choose, or does an event force it?

THE MODEL DECIDES

Skill

A capability the model can choose to invoke when it's relevant — like a function it decides to call. Your /mentoring-session-prep is a skill. The model read the request, judged it relevant, and ran it. Optional, model-driven.

VS
THE EVENT DECIDES

Hook

Deterministic code that fires automatically on a lifecycle event — the model has no say. The "rate this 1–5" prompt after a skill is a Stop hook: it runs because the turn ended, not because the model felt like asking. Forced, event-driven.

In your world: the Writer agent deciding to call the LLM = skill-like (logic chooses). A DB trigger that fires on every INSERT into ai_summaries = hook-like (the event fires it, not your code's choice). You already use both patterns.

What's the "harness"?

A word that gets dropped without definition. Here it is in plain language.

The harness is the program that runs the agent — the loop wrapping the model. It is not the AI. It's the deterministic code that: feeds the model your message, runs the tools the model asks for, enforces permissions, manages the context window, and fires the hooks at lifecycle events. The model is the brain; the harness is the body and nervous system around it.

Your analogy: in nightly-summary, the LLM writes the roast — but the surrounding TypeScript (build the payload, loop the 5 variants, call the Judge, save to DB, fallback on failure) is the harness. You already wrote a harness. Claude Code's is just bigger.

Anatomy of a skill

A skill is a folder. Two parts the loop cares about.

# my-skill/SKILL.md --- name: my-skill description: what it does + when to use it + trigger phrases allowed-tools: Read, Write, Bash --- # Body — the instructions the model follows when the skill runs # my-skill/references/ good-001.md ← an exemplar: "this is what a 5/5 run looks like" good-002.md ← the loop READS these to self-improve at rating 4 good-003.md ← the loop WRITES a new one here at rating 5
The good-*.md files are to a skill what your prompt_versions rows are to a prompt: versioned snapshots of "what good looks like", that the system reads from and writes to over time.

⚡ The self-improving loop — try it

A skill just finished. The Stop hook asks: "rate it 1–5". Pick a score and watch where the system routes itself.

RATING 1–3

Ask me

The skill clearly missed. The loop asks the user what was wrong, then proposes a concrete edit to SKILL.md. Human-in-the-loop because the gap is unknown.

RATING 4

Self-diagnose

Good, not perfect. The loop reads its own good-*.md exemplars, diagnoses the gap by itself (no questions), and proposes a fix. It has enough signal to learn alone.

RATING 5

Bank the win

This run was exemplary. The loop saves it as a new good-*.md — tomorrow's "what good looks like". The bar rises automatically.

👆 Pick a rating above to route the loop.
↔ Your Judge: the rating is the rubric score. The 3 branches are your threshold gating — the idea you proposed yourself in Meeting 5: below a threshold → fallback; above → keep. Same control flow, applied to skills.

The meta-moment

Why this is continuity, not a new concept.

Skills & Hooks (tooling layer)

Key takeaways

  • Skill = model decides to invoke a capability. Hook = an event forces deterministic code to run. The split is "who decides".
  • Harness = the loop around the model (tools, permissions, context, hooks). Not the AI — the body around it. You already wrote one in nightly-summary.
  • The skill-rate Stop hook turns a score into a route: 1–3 ask · 4 self-diagnose from exemplars · 5 save a new exemplar.
  • good-*.md exemplars ≈ your prompt_versions: versioned "what good looks like" the system reads and writes.
  • It's your Judge/rubric/threshold idea applied to tools instead of summaries — continuity, not a new concept.
